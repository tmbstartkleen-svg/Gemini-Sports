# TravAI v5000000000 — Elite Always-On Autonomous Runtime

## Purpose
v5B turns TravAI from an application you manually launch into a resilient local AI runtime that can persist queues, schedules, health checks, and bounded background agents across server restarts and macOS logins.

## Runtime guarantees
- Persistent queue stored in `data/always-on-runtime-v5000000000.json`.
- Any job found in `running` state after restart is recovered to `queued`.
- Retries are bounded (1–6 attempts) with exponential delay.
- Schedule and agent cadence is bounded to 60 seconds–7 days.
- Only an explicit internal job catalog can execute in the v5B runtime.
- v5B has no arbitrary shell or arbitrary URL runner.
- Sensitive file/repository/account mutations remain governed by v3B/v4B approval gates.

## Safe background job catalog
- `runtime.health`
- `v4.memory.control`
- `v4.knowledge.index`
- `v4.plugins.discover`
- `v3.connector.health`
- `v2.model.discover`
- `v1.hybrid.health`

## macOS auto-start
Run once:

```bash
bash scripts/install-launch-agent.sh
```

The installer creates `~/Library/LaunchAgents/com.travai.runtime.plist`, uses the current Node binary and TravAI folder, starts TravAI at login, and requests relaunch after abnormal exits.

Remove it with:

```bash
bash scripts/uninstall-launch-agent.sh
```

## Remote-control foundation
The remote inbox is off by default. It requires both:

```bash
export TRAVAI_REMOTE_ENABLED=1
export TRAVAI_REMOTE_TOKEN='a-long-random-secret-at-least-24-characters'
```

The server still binds to `127.0.0.1`; v5B does not expose TravAI to the public network. Remote access should be provided later through a secure authenticated tunnel/VPN layer. Remote submissions can only enqueue the same allowlisted runtime jobs.

## Evidence
Runtime events are appended to `data/always-on-events-v5000000000.jsonl`. Queue/schedule/agent state is persisted separately from credentials and contains no remote token.
